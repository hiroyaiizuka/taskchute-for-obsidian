# TaskChute for Obsidian（TaskChute Plus）

[English](./README.md) | [日本語](./README.ja.md)

📖 **公式ドキュメント:** https://obsidian.levers.co.jp/ja/

**タスクを整理するだけでなく、実行するためのプラグイン。**

TaskChute for Obsidian（TaskChute Plus）は、大橋悦夫さんが考案したタスク管理メソッド「タスクシュート」を Obsidian で実践するための公式プラグインです。  
大橋さんが代表理事を務める一般社団法人タスクシュート協会の公認を受けています。

実行重視のタスク管理で、「今やること」を決めて実行し、実績ログを蓄積して改善につなげます。

## できること

- 日付ナビゲーション付きの TaskChute ビューで当日のタスクを管理
- タスクの開始/停止と実作業時間の記録
- カスタム可能な時間帯スロット + `時間指定なし` での表示
- ルーチン（毎日/毎週/毎月）の作成と運用
- タスクインスタンスの移動・複製・リセット・削除（day state 永続化）
- タスクとプロジェクトの紐づけ、およびプロジェクトボード表示
- 実行ログと年次ヒートマップの確認
- タスクごとのリマインダー設定
- 実行中のタスクへのコメント、その日のコメント（今日のコメント）
- レシピ（完了基準・手順・品質基準・制約をまとめた仕事の進め方）をタスクに設定
- Google Calendar URL スキームへのエクスポート
- AIタスク（Pro）: Claude Code・Codex・Cursor に仕事を任せ、ターミナルで動かす（デスクトップのみ）
- 日本語/英語 UI（Obsidian の言語設定に追従）

## コマンド

Obsidian のコマンドパレットから利用できます。

- `Open TaskChute`
- `TaskChute settings`
- `Show today's tasks`
- `Reorganize idle tasks to current slot`
- `Duplicate selected task`（TaskChuteビューがアクティブ時）
- `Delete selected task`（TaskChuteビューがアクティブ時）
- `Reset selected task`（TaskChuteビューがアクティブ時）

## はじめ方

### Obsidian へのインストール

1. `Settings -> Community plugins` を開く
2. `TaskChute Plus` をインストールして有効化
3. `Open TaskChute` コマンドを実行

### 最初のタスク

TaskChute の UI から作成するか、タスクフォルダに手動でノートを作成します。

最小の手動例:

```md
---
tags:
  - task
target_date: "2026-04-16"
scheduled_time: "09:00"
---

# オンライン診療
```

互換性のため、本文中の `#task` タグ検出もサポートしています。

## 設定概要

`TaskChute settings` で次を設定できます。

- 保存先モード（`vaultRoot` / `specifiedFolder`）
- プロジェクトフォルダ（任意・独立パス）
- レビューテンプレートパスとファイル名パターン
- 今日のコメント（初期はオフ）、レシピ機能（初期はオフ）
- 既定リマインダー分数
- 実行ログスナップショットのバックアップ間隔/保持期間
- カスタム時間帯境界と時間帯折りたたみUI
- Google Calendar エクスポート既定値
- Pro設定：ライセンスの有効化、デバイスのシート管理、それによって使えるAIタスクの各種設定（デスクトップのみ）

現行コードのデフォルト値:

- `backupIntervalHours: 2`
- `backupRetentionDays: 1`
- `defaultReminderMinutes: 5`
- `locationMode: vaultRoot`

## デフォルトの保存パス

`vaultRoot` モードでは、TaskChute 管理フォルダは次になります。

- `TaskChute/Task`
- `TaskChute/Log`
- `TaskChute/Review`

`projectsFolder` はデフォルトで未設定です（必要時に個別指定）。

## AIタスク（Pro・デスクトップ専用）

タスクを AI エージェント（Claude Code / Codex / Cursor）に任せ、タスクリスト下の「AI実行」ペインに埋め込まれた本物のターミナルで動かします。対話型のTUIがそのまま描画され、タスクの指示が自動で渡されたあとも、自分のターミナルで CLI を起動したときと同じように、いつでもセッションに直接入力できます。

使い方の詳細は公式ドキュメントを参照してください: [AIタスクとProライセンス](https://obsidian.levers.co.jp/ja/howto/pro-license)

- **Proライセンス**の有効化が必要です。`TaskChute settings` → `Pro 設定` でアクティベーションコードを入力し、`AIタスクを有効化` をオンにします。同じページで、使用中の端末の一覧と解除も行えます。アクティベーションコードは端末ごとに保存され、同期されません。送信内容は[ネットワーク通信について](#ネットワーク通信について)を参照してください。
- 動く環境: Windows（Windows 10 バージョン 1809 以降）・macOS・Linux。モバイルでは動作しません。macOS と Linux では、ターミナルの実行に Node.js を使います。
- プラグインは手元にある CLI を起動するだけです。**Claude Code（`claude`）・Codex（`codex`）・Cursor（`cursor-agent`）のインストールと認証は、各自で事前に済ませておく必要があります。** プラグイン自身は API キーを扱いません。CLI は各自が認証したアカウントで、それぞれの提供元と通信します。
- CLI は自動で検出します。見つからない場合だけ、`Pro 設定` の `CLIパス（詳細・予備）` に絶対パスを指定してください。

### ネットワーク通信について

プラグインがネットワーク通信を行うのは、Proライセンスの検証のためだけです。通信先はライセンスAPI `https://taskchute-license.levers.workers.dev`、経路はHTTPSです。

- **通信のタイミング** — アクティベーションコードの登録時とデバイスのシート解放時、`Pro設定` ページでシート使用状況を一覧するとき（最短1分に1回まで）、そしてこのデバイスに保存された署名付きトークンの有効期限が近いとき（12時間ごとに確認、トークンの有効期間は7日）。更新の合間はトークンをオフラインで検証するため、接続がない環境でもそのまま利用できます。
- **送信する内容** — ライセンスコード、このプラグインが生成したランダムなデバイスID、デバイスの一覧でシートを見分けるためのラベル（マシンのホスト名、取得できない場合はプラットフォーム名と、Vault名）、プラットフォーム名、プラグインのバージョン。
- **送信しない内容** — タスク・ノート・ログ・プロンプトの内容は一切送信しません。テレメトリや利用状況の収集も行いません。上記以外にネットワーク通信を行う箇所はありません。

### タスクの作り方

AIタスクは、タスクの作成画面で `タスク種別` → `AIタスク` を選んで作ります（既存のタスクは ⚙ → `🔁 種別を変更`）。エージェント、指示（プロンプト）、実行モード（マニュアル / オートモード / 権限スキップ）、モデル、推論モード、ワーキングディレクトリ、レシピを画面で選べます。設定はタスクノートの frontmatter と `## Prompt` セクションに保存されます。

```markdown
---
ai_task: true
ai_task_host: claude        # claude（デフォルト）/ codex / cursor
ai_task_cwd: Projects/demo  # 任意: 作業ディレクトリ（Vault相対または絶対パス）
ai_task_args:               # 画面で選んだ実行モード・モデルなど
  - --permission-mode
  - auto
---

## Prompt

このプロジェクトの未解決の論点を要約し、次のステップを提案して。
```

- `ai_task_args` のうち、CLI に渡すのは作成画面で選べる引数だけです。それ以外の引数は使わず、お知らせを出します（同期・共有されたノートが、CLI の動きを勝手に変えないため）。
- 「権限スキップ」と、Vault の外の作業ディレクトリ（と、Cursor の「このフォルダを信頼」）は、この端末での許可が必要です。▶ で初めて始めるときに確認が出て、許可はこの端末だけに保存されます（同期されません）。

### 実行のしかた

- タスク行の ▶ で始めると、「AI実行」ペインにターミナルのタブが開きます。＋ で普通のターミナル、◫ で分割、ファイル一覧でワーキングディレクトリのファイルを開けます。
- 実行ごとにログノート（色制御コードを除去したターミナルのトランスクリプト）が `TaskChute/AI/Logs/YYYY-MM/` に保存され、`実行ログの保持期間（日）`（デフォルト30日）より古いログノートは自動的にゴミ箱へ移動されます。
- **セッション履歴**: Vault のフォルダで動かした Claude Code / Codex / Cursor の過去の会話を一覧・全文検索し、続きから再開できます（コマンド `AI のセッション履歴を開く`）。
- **自動実行**: ルーチンにした AIタスクは、開始予定時刻になると自動で始まります（1分ごとに確認、1日1回）。自動で始まるときは確認ができないため、「権限スキップ」は許可がなければオートモードで動き、許可していない作業ディレクトリでは始まりません。
- **人間のタスクとの連動**: ルーチンの設定の「Obsidian連携」で、決めた名前の人間のタスクを始めると AIタスクも始まるようにできます。止める・戻す・削除・日付の移動も連動します。
- **レシピ**: AIタスクにレシピを設定すると、完了基準・手順・品質基準・制約が最初の指示に添えて渡されます。

### ターミナルが使えないとき

- ターミナルはどこでも既定で使います。使えない環境では「会話モード」で動き（CLI を非対話で実行し、イベントをペインに表示、追加の指示はペインの入力欄から送る）、理由を通知します。
- **Windows** では、標準搭載の Windows PowerShell が起動する Windows の疑似コンソール（ConPTY）の中でターミナルを実行します。追加でインストールするものはありません。Windows 10 バージョン 1809 以降が必要です。最初のターミナル実行時に疑似コンソールが使えるかを確認し、使えない環境（古いビルドや、管理ポリシーで PowerShell が制限されている場合）では会話モードで実行します。Windows ではペインから素のシェルセッション（＋・分割）は開けず、ターミナルのセッションは CLI の終了とともに終わります。
- **ターミナルが始まらないとき**: ターミナルは、Obsidian を再読み込み・更新しても動き続ける別のプロセス（ブローカー）の中で動きます。Node.js を更新したあとなど、ブローカーがターミナルを始められなくなったときは、ほかにターミナルが動いていなければ、ブローカーを作り直して自動でやり直します。ターミナルが動いているときは、失敗の通知の「ターミナルを再起動」ボタンか、コマンド `AI のターミナルを再起動` で作り直せます（動いているターミナルは終わります）。

## 開発

### 要件

- Node.js 18+
- npm

### セットアップ

```bash
npm install
```

### スクリプト

```bash
npm run dev       # esbuild watch
npm run build     # production bundle
npm run lint      # eslint for src/tests
npm run test:unit        # jest（ユニット）
npm run test:integration # jest（*.integration.test.ts / 実プロセスを起動）
```
